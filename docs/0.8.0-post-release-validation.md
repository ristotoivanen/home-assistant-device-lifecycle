## Findings

### PRV-080-01 — note

| Source | Active | Archived |
|---|---|---|
| Dashboard "Device Lifecycle FI" | 32 | 3 |
| Canonical Store | 33 | 2 |

The dashboard template counts Lifecycle states `retired`/`disposed`/`lost` as "archived" instead of using canonical `archived_at`. The affected dashboard calculation includes DL0018, DL0021, and DL0022.

Disposition:

- Not a Device Lifecycle integration defect.
- No data-safety impact.
- The dashboard template/terminology should be fixed separately.
- Does not require 0.8.1.

### PRV-080-02 — note

Two Purchases have `configured=false` while retaining `config_subentry_id` references to removed subentries:

| Purchase | Assets |
|---|---|
| Shellyn aitan socket | 0 |
| 2026 /08 Testiostos | 2 |

This is intentional historical persistence behavior.

Disposition: **ACCEPTED / EXPECTED.** No change required.

### PRV-080-03 — note

The `archive.py` module docstring still states that Archive/Restore mutations are not used in production. That wording is stale in 0.8.0.

Disposition:

- Source-comment/documentation debt.
- No runtime impact.
- Does not by itself justify 0.8.1.

`archive.py` was not modified in this documentation task.

### PRV-080-04 — note / test coverage

The production audit did not execute:

- Maintenance Record / Mark done.
- Disabled schedule behavior.
- Archived Asset Maintenance entity behavior.
- Active Runtime accumulation through restart.

These are production-environment safety/test limitations, not observed defects. They remain **NOT TESTED** in this production audit; pre-release Test HA evidence is separate.
