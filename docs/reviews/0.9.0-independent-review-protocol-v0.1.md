## Independence rule

Assign to three **genuinely different AI models/systems**, e.g. Claude, Gemini and Codex, with one initial reviewer brief each. Do not present model A's conclusions to model B or C before their **initial** reports are sealed. Model labels must record the actual tool/model used; do not simulate a separate reviewer by changing the prompt in one conversation.

All reviewers must use the exact same input commit. Ask for a falsification attempt, not confirmation. They must distinguish \`VERIFIED\`, \`CONTRADICTED\`, \`UNKNOWN\`, \`NOT TESTED\` and \`PROPOSED\`; "looks good" carries no evidence.

## Mandatory review report format

Each independent report should be saved later as \`docs/reviews/0.9.0-review-{a|b|c}-<actual-model>-v0.1.md\` and contain:

1. Model/system, date, immutable reviewed commit SHA, exact documents/code reviewed, access limitations.
2. Executive result: \`BLOCKING\`, \`MAJOR\`, \`MINOR\`, \`NOTE\` or \`NO FINDINGS\`; never "APPROVED" by the reviewer.
3. Numbered findings \`R{A|B|C}-NN\`: severity, **specific** path + line/function, invariant/requirement, minimal failure scenario, evidence status, remediation constraints and discriminating test.
4. Any unresolved questions explicitly \`UNKNOWN\` / \`NOT TESTED\`. Absence of evidence is not PASS.
5. Cross-reference the Master Architecture's \`OD-xx\` decisions; nominate additional decisions where needed.
6. No repository changes or design freeze without separate owner authorization.

## Cross-challenge and adjudication

1. Seal reports A/B/C independently using the same input commit.
2. Share their *findings* across the reviewers for a **second, labeled cross-challenge pass**. Ask each to falsify competing findings, identify missing failure cases and distinguish duplicate from contradictory claims.
3. Aggregate every claim as \`ACCEPTED / REJECTED / DEFERRED / UNRESOLVED\` with owner rationale, exact evidence, impacted \`OD-xx\` and target design revision. Rejected reports remain visible and reasoned; no silent deletion.
4. Update the Master and domain design drafts to resolve blocking conflicts; commission independent re-review of the **new immutable commit**, not the original.
5. Owner makes final approval decision. Design freeze requires: no unresolved BLOCKING/MAJOR defect, every OD-01–OD-08 resolved with evidence, explicit acceptance of residual risks, full requirement-to-test traceability, and reproducible review artefacts.
6. Reviewer outputs are assessments, **not** authoritative implementation approvals.
